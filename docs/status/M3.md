## Architecture and consistency model

- SQLite state uses WAL, foreign keys, busy timeout and `BEGIN IMMEDIATE` application transactions.
- Migration `001` creates nine required domain tables plus `workspace_leases`; `schema_migrations` is created by the migration runner. Migration version/checksum is idempotently verified.
- Artifact bytes publish atomically to a SHA-256 store before DB metadata binds them. Reopen hashing proves exact bytes. This cross-resource boundary is recovered rather than falsely treated as one atomic transaction.
- Unique constraints protect workflow stage identity, logical `(stage, orientation, basename)` transactions, call attempt indexes, artifact digests/paths, committed bindings and workflow event sequences.
- Published artifacts become read-only. Role/owner-stage mismatches fail before store write.
- Progress is derived from committed transactions and current gate state. Candidate, quarantined, interrupted and stale evidence never increments it.
- Events store canonical JSON, digest and monotonic per-workflow sequence. Public APIs expose append only.
- Workspace leases detect a second active owner and allow takeover only after UTC expiry.

## Recovery and failure injection

Tests cover interruption before temp write, after temp write, after rename/before DB bind, injected DB failure, path/disk-volume failure, digest mismatch, duplicate commit, retry after timeout, missing committed file, stale dependency and read-only mutation. At least one restart test closes and reopens the database/store through a new `WorkflowKernel` instance.

Recovery preserves unbound published bytes, defers narrow temp cleanup, blocks DB/file inconsistencies, marks running calls timed out, returns in-progress transactions to retryable state without changing transaction ID, stales affected gate history, and records resume events.

## Limits

- M3 uses fake byte producers only; actual LLM/image/OCR adapters begin in later milestones.
- Store publication plus SQLite binding is recoverable but cannot be atomic across filesystem and database.
- Lease expiry uses wall-clock UTC; hostile clock rollback is outside the single-user MVP threat model.
- Recovery preserves content-addressed store orphans rather than deleting potentially valuable bytes.
- Backup/restore tooling is deferred to M11.
- This report records the reviewed M3 implementation and its final pre-commit evidence. M4 has not started.
